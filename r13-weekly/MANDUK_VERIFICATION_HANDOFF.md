1. 만덕이 검증계의 **승인된 저장소·브랜치·배포 경로·프런트 스택**을 확인하고 별도 테스트 브랜치를 만든다.

3. CSS/JS를 현재 운영 번들/라우트와 섞지 않는다. 실제 결제 버튼/PG 호출로 연결하지 않는다.
4. 검증계 도메인에서 수동 UI QA를 실시하고 사용자에게 프리뷰 URL을 공유한다.
5. 만덕이 가격, 권한, 결제 계약을 승인하고 백엔드 책임 영역을 준비한 다음 **새 통합 PR**에서 운영 이관을 결정한다.
6. 사용자 지시 없는 운영 브랜치 병합/배포는 하지 않는다. 만덕이 직접 실제 배포 책임을 가진다.

## 7. UX 위험
- 현재 페이지에 기록된 가격은 **가상·미승인**이다. 실판매 페이지에서는 결제 총액, 부가세, 유효기간, 이용권 활성화, 환불 조건을 실제 정책과 검증하고 표시해야 한다.
- 무료 첫 판정에서 필요한 위험 신호를 감추지 않는다. 분석 완료/결제 성공처럼 오인될 만한 시연에는 항상 '시연용'을 붙인다.
- 공유 문구는 실제 고객 후기나 상권 분석 결과가 아니다. 실제 공유 기능을 만들 때 개인 후보지와 업종 정보가 자동 공개되면 안 된다.
- 별도 실험 URL의 `noindex,nofollow`는 검색 엔진에 대한 안내일 뿐 접근 제어가 아니다. 비공개 실험이 필요하면 Netlify/검증계에서 접근 제어를 별도로 적용한다.
